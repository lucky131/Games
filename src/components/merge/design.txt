    itemLibrary.js  每件装备的 stats / cooldown / effect / hooks（含 drawItem 抽卡逻辑）

一、核心规则
------------------------------------
1. 角色  双方各一个角色，只有 HP，无其他属性。
2. 时长  每场 30 秒。超时后第 N 秒对「双方」造成 N×0.5% 最大生命值的真实伤害，逐秒递增。
        一方 HP 归零即结束；平局算玩家失败。
3. 棋子  每个棋子有独立冷却，冷却结束自动释放 effect。
        纯被动装备 cooldown = 0，不自动释放，只靠 hooks 生效。
        技能急速按 cd × 100/(100 + AH) 缩短冷却。
4. 战斗前  玩家可自由摆放 / 卸下棋子，仓库用于临时存放。
          state === 'fighting' 期间禁止买卖、装卸、合成。
5. 本局  共 10 波，玩家 3 颗心，输一波扣一颗，扣完本局结束，只能重新开局。


二、装备体系与商店
------------------------------------
| 等级 | 件数 | 价值 | 获取方式 |
| 一级 | 8  | 3c（买卖同价） | 商店全程可刷 |
| 二级 | 24 | 8c（买入 11c） | 第 6 回合起商店可刷，或用两件一级合成 |
| 三级 | 54 | 13 / 16 / 18 / 21 / 26c | 商店不刷，只能合成 |

商店刷新是两步抽卡：每个格子先按 LEVEL_WEIGHT_TABLE 掷「等级」，
一级再按**商店池的剩余库存**加权抽「哪一件」（库存 0 的进不了候选），二级在池内等概率。

- 等级权重只取相对关系，不必凑成 100。
- 三级列恒为 0：三级只能合成。这一列保留是为了将来放开时只改数字，不必动 drawItem。
- [已废弃] 「每件装备自带固定 weight、全局按 weight 抽」的旧机制：
  三个池子大小 8 / 24 / 54 差一个量级，权重不在同一量纲，跨等级根本调不准。
  现一律「先掷等级，再在池内抽」；一级的固定权重也被库存取代（见下）。

一级装备池（LEVEL1_POOL_SIZE_TABLE / itemPool.js）：
- 初始库存：红水晶 / 长剑 / 增幅典籍 12，荧尘 / 布甲 / 抗魔斗篷 8，治疗宝珠 / 蓝水晶 4，合计 68。
  因为抽取权重 = 剩余库存，开局出货比例就是这张表本身的 12 : 8 : 4。
- 抽取时预留：格子抽到一级就扣库存，刷新商店时未售出的一级格归还。买走即永久离开池子。
- 合成消耗的材料**不归还**，是池子唯一的永久漏出。
- 卖出装备**递归归还**：一级还 1 件，二级 / 三级沿配方树拆成一级材料逐个归还。
  不区分来源，商店直接买的二级卖掉也照样拆，所以池子允许超过初始值。
- 豁免：不走商店的一级装备（开局长剑、时光之杖白送件、dev 直取）既不扣也不占用池子。
- 一级池全空时该格改出二级，保证商店不出空格子（合计 68 时仍属安全网，正常玩不满）。
- 只约束玩家商店，敌人（enemyBuilder.js）不受影响。

[注意] 池子是隐藏状态，改变的是随机分布而不是「抽得到 / 抽不到」，玩家天然会归因为运气，
       所以商店浮窗必须显示一级装备的剩余库存。
[风险] 权重 = 剩余库存带有正反馈：长剑 / 红水晶 / 增幅典籍 既是最常被消耗的材料、
       初始库存也最高，越用越少越难抽，而低需求的蓝水晶相对变多，后期分布会漂移。
       这是刻意的取舍（让池子真的能被玩空），若实测体感不对，改回「固定权重 + 库存闸门」即可。

商店格数随回合增长（SHOP_SLOT_TABLE，5 → 7），只在换回合时增减。
后期池子更大、多给格子，属于纯增益，经济侧没有对冲。


三、合成与价格体系
------------------------------------
三个概念必须分清：

| 概念 | 含义 | 存哪 |
| 价值 value | 内在价值，等于出售返还价 | 不写配置，模块加载时递归推导 |
| 买入价 price | 商店售价 | 不写配置，由价值反推 |
| 合成成本 | 材料价值之和 + 合成费 2c | recipes.js，恒等于价值 |

规则：
- 一级装备没有配方，价值 = 商店价，买入卖出同价。
- 二级 / 三级：出售返还 = 买入价 × SELL_RATE(0.7)。
- 买入价 = ceil((价值 - 0.5) / 0.7)，保证「买进立刻卖出」不净赚。
- 价值自底向上递归：一级 = 商店价；二级 / 三级 = 材料价值之和 + 2c。
- 商店价永远高于合成成本，差额 =「免凑材料的便利费」，否则没人会去凑材料。
- 三级价值不是一个固定值（13 / 16 / 18 / 21 / 26 五档），取决于材料里掺了几件一级装备。
  纯二级材料的三级装更贵更强，掺一级的更便宜——这是刻意的。
- 新增三级装备只写 materials + goldCost，价值与买入价自动跟着材料组合推导。
- 同材料重复配方是刻意保留的：同一组材料可以做出多件装备，由玩家按本局阵容自己选。
  三级阶段尤其密集。


四、属性系统
------------------------------------
| 属性 | 作用 |
| hp | 加角色最大生命值，由棋盘 computed 汇总 |
| armor / mr | 减物理 / 魔法伤害，公式 抗性/(抗性 + RESIST_CONSTANT) |
| ah 技能急速 | 冷却 × 100/(100 + AH) |
| pen / magicPen | 只减「对应伤害类型减伤用的有效抗性」 |
| mrShred / ahShred | 只减「对方」的魔抗 / 急速，在棋盘 computed 里按阵营相减 |
| healPower | 每点 +1% 治疗量 |
| physAmp / magicAmp | 己方所有该类型伤害 ×(1 + n/100)，在敌方抗性减伤之前乘 |

- 减益类（mrShred / ahShred）走 stats 通道，但在棋盘 computed 里按阵营相减，
  属性面板与伤害结算读到的始终是同一个值，不在受击 / 冷却换算时临时扣。
- 伤害倍率不做成面板属性：不显示是刻意的，但仍走 stats 通道聚合，
  将来加 conditionalStats 不用另开一套机制。
- healPower 不是空转属性：所有治疗都会被该阵营的 healPower 放大。
- [无] 攻速、暴击率、韧性、移速。吸血是各装备写死的百分比，不是全局属性。
- [无] 攻击力(AD) / 法术强度(AP) 不作为全局属性。曾作为 stats 字段存在但无人消费，已删除。
  当前所有伤害数值硬编码在各装备的 effect 里。
- 装备描述的数值只有一个来源：stats。
  itemLibrary 的 desc 只写「非属性」的说明（如 3.0s 15 魔法、战斗结束 +1c），
  属性加成由 formatDesc(stats, desc) 在模块加载时拼到 desc 前面。
  改数值只需改 stats；新增属性只需在 STAT_LABELS 里补一条中文名。


五、战斗管线
------------------------------------
入口 dealDamage(from, target, amount, damageType, isBonus)，按顺序：

0. 伤害倍率：物理 / 魔法各一条，初始 1.0，在敌方抗性减伤之前乘。
   来源是攻击方阵营的 physAmp / magicAmp 合计。真实伤害与无 owner 的系统伤害不吃。
1. 减伤
   physical：有效护甲   = 目标护甲 - 攻击方 pen
   magic   ：有效魔抗   = 目标魔抗 - 攻击方 magicPen
   true    ：不减免
   有效抗性下限 MIN_EFFECTIVE_RESIST（-50）：压到负数即等价于增伤（-50 → 伤害 ×2），
   再低也不继续放大，避免 4~5 件穿透装同场时除零或算出负伤害。
   公式 amount × (1 - 有效抗性/(有效抗性 + K))，向下取整，最低 0。
2. 先扣护盾，护盾吸收完仍有剩余才扣血。
3. 返回值是实打实的伤害总量（含被护盾吸收的部分），吸血类按此计算。

钩子（都在伤害结算之后广播）：

| 钩子 | 广播对象 | 时机 |
| onDealDamage | 造成伤害方的全部棋子 | 每次伤害事件一次；isBonus 为真时跳过 |
| onDamaged | 受击方的全部棋子 | 用 _processingOnDamaged 防止反伤递归 |
| onHeal | 治疗来源方的全部棋子 | 每次治疗事件一次；isBonus 为真时跳过 |
| onBattleStart | 指定阵营的全部棋子 | 双方锁阵容、ahRate 写好之后、开打之前 |
| onOvertimeTick | 指定阵营的全部棋子 | 超时每跨过一个整秒 |
| onSell | 被卖掉的那一件 | 商店阶段，唯一不在战斗里的钩子 |
| onBattleEnd | 玩家场上全部棋子 | 见七节，只记账不发钱 |

isBonus 是防递归的唯一手段：附加伤害 / 附加治疗带 isBonus=true，不再触发同类钩子。
反甲反伤、反曲之弓一次打两种伤害都算「主动伤害」，照常各触发一次。
onDealDamage 会把 damageType 塞进 ctx，供「按伤害类型计数」的装备判断这一发。

onBattleStart 广播时对棋盘做快照，所以钩子里新塞进去的装备不会被同一轮顺带触发。
onSell 的广播对象只有被卖掉的那一件，ctx 为此有 addLife(amount)（敌人没有「心」）。
「心」= ❤ 生命（输赢计数），与面板上的「生命值」HP 是两回事。

超时：
- 首次跨过 0 秒时给双方每件棋子置 overtime = true，并按（可能已被 conditionalStats
  抬高的）技能急速重算一次冷却。
- 超时每跨过一个整秒：先结算超时真伤（无 owner，不触发钩子），再广播 onOvertimeTick。
- 战斗结束时收回 overtime，否则「超时后才有加成」的高亮边框会一直亮到下一场开战。


六、护盾与层数
------------------------------------
护盾
- 角色有 shield 字段，玩家 / 敌人各一份，startBattle 与 continueGame 时清零。
- ctx.addShield(target, amount, from)，from 传自身，结算面板据此把护盾归到具体装备。
- 血条上以亮青色段显示在血量段之后；血量 + 护盾超过最大值时按比例压缩。
- 无上限、无衰减。
- 护盾可以主动「喂」给敌方：夜之锋刃 / 中娅沙漏各给敌方挂 1 点护盾，是刻意为之——
  巨蛇之牙 / 影焰「敌方有护盾就提高伤害」正好吃这一口，把盾变成双刃剑。

层数
- Chess 类持有 maxStacks（>0 有上限，-1 无上限，0 = 无层数）与 stacks。
- 类只负责层数增减与显示开关，具体效果写在各装备自己的 effect 里。
- 图标左下角显示层数角标，仅 maxStacks !== 0 且 stacks > 0 时出现。

| 字段 | 作用 |
| maxStacks | >0 有上限；-1 无上限；0 = 该装备没有层数系统 |
| initStacks | 战斗开始时的初始层数（默认 0）。用于「层数 = 剩余次数」的装备 |
| statsPerStack | 每层的属性加成，由 sumStat 按「当前层数 × 每层值」实时折算 |
| keepStacks | 层数是否跨回合保留。默认 false：开战回到 initStacks、战斗结束归零 |

按用法分两类：
- 战斗内累积、结束清零：狂热 / 三相之力（冷却）、千变者贾修（护甲魔抗）、
  黑色切割者（物穿）、放血者的诅咒（法穿）、裂隙制造者 / 鬼索（满层解锁）、
  残疫（计数到 10 层给法穿）、斯特拉克（层数 = 剩余触发次数）
- 跨回合累积：心之钢、时光之杖、无穷饥渴、狂妄、梅贾的窃魂卷

层数带来的冷却缩减写在 effectiveBaseCooldown 上，每场由 startBattle 重置回 baseCooldown。
「满层才解锁行为、不加属性」的装备用 conditionalStats 返回 {} 来点亮高亮边框
（{} 非 null 即「加成生效中」，见十节）。

[注意] 成长类装备（心之钢）的成长挂在「棋子自己」身上，不是角色属性：
棋子一离开棋盘（卸下 / 出售 / 进仓库），sumStat 就不再聚合它，上限立刻回落；
上限下降时由 maxHp / enemyMaxHp watcher 把当前血量夹到新上限，否则出现 hp > maxHp。
效果顺序必须是「先伤害 → 再涨上限」，叠层量取自 dealDamage 的返回值。
改挂棋子之前存在「合成 → 上场叠满 → 卖掉 → 下回合重来」的零成本套利，现已堵住。


七、战斗结束结算与收入
------------------------------------
分两段，避免「面板显示」和「实际发钱」重复计算：

1. endBattle —— 只记账，不发钱。
   buildIncomeBreakdown(isWin) 写入基础收入与胜负奖励，挂到 battle.incomeBreakdown；
   然后 emitHooks('onBattleEnd', 'player', { isWin }) 触发玩家场上所有装备的 onBattleEnd。
   isWin 一并广播（无穷饥渴 / 狂妄 / 梅贾的窃魂卷要在钩子里判胜负叠层）。
2. 装备在自己的 onBattleEnd 里用 ctx.addIncome(name, amount) 申报收入（只写明细，不改 player.money）。
3. continueGame 按 incomeTotal 一次性加到 player.money。

- emitHooks(eventName, owner) 只广播指定阵营，所以只有玩家场上的装备计入收入面板。
- 明细顺序：基础收入 → 胜负奖励 → 各装备（按棋盘格顺序）。
- emitHooks 先对棋盘做快照再遍历：时光之杖的 onBattleEnd 会往棋盘里塞一件新装备，
  直接遍历原数组的话它会被同一轮顺带触发。

ctx.addMoney(target, amount) 是另一条路：战斗中途直接改 player.money，不写收入明细。
两条路互斥，走 addMoney 的结算时不会再发一次。
目前仅卢登的回声使用（每 5 次攻击 +1c），目的就是让夺萃之镰能读到刚涨的这一笔；
若攒到 onBattleEnd 再申报，夺萃之镰整场都看不到这笔钱。战斗中这笔钱只能攒着。


八、经济节奏
------------------------------------
衡量口径只有一个：第 10 回合开打前手上有几件三级装备。
第 10 回合的收入打完就 endGame、花不掉，所以有效收入只有 9 个回合。

| 玩法 | 有效毛收入 | 净资产（扣约 20% 刷新/溢价） | 三级装件数 |
| 全胜 + 精打细算 | 113c | 90c | 5 件 |
| 全胜 + 浪费 35% | 113c | 73c | 4 件 |
| 失败 2 次 | 135c | 108c | 6 件 |
| 全胜 + 1 件禁忌雕像 | 129c | 103c | 5.7 件 |

三级装均价 19.1c，最标准的 18c 档占 39%。这套数字只在纸面推演过，未实测。

[重要] 表里「失败 2 次」的件数高于「全胜」，是刻意的，不是表格算错：
       失败不推进回合、失败场照拿基础收入，所以「场次」本身就是资源。
       数值上主动输几场确实更肥——满血通关不是强度最优解，而是玩家自我设限的挑战目标；
       输是合法退路，代价只有 3 颗心（见十一节决策 1）。

三条支撑它的事实：
- 金币可全额回收，不是消耗品：卖出返还 item.value（= 材料价值之和 + 合成费），
  一级装又买卖同价，合成路径零损耗。唯一的真漏出是刷新费与商店直购的溢价。
  推论：最终资产 ≈ 累计毛收入 - 刷新费 - 溢价，金币只决定「一次性最多能搭多大的树」。
- 棋盘 6 格是硬上限，6 件三级装就是天花板，经济装与三级装争的是同一批格子。
- 失败不推进回合（continueGame），多打一场就多一份收入——这是「失败 2 次 → 6 件」成立的原因。


九、敌人波次
------------------------------------
两张表都在 gameConfig.js，enemyBuilder.js 只负责查表 + 抽装备。

ENEMY_LEVEL_TABLE（每回合 [1级数, 2级数, 3级数]）
  价值从第 1 回合的 3c 线性增长到第 10 回合的 81c（口径：一级 3c / 二级 8c / 三级 19c），
  每回合取「价值最接近目标、同价值下优先高等级」的组合。
  两条硬约束：三项之和 ≤ BOARD_SLOTS、价值必须单调递增。

  [注意] 「优先高等级」让中间几回合的件数骤降：第 5 回合目标 38c 的最近组合是 [0,0,2]，
  全场只有 2 件装备。根源是三级 19c 与二级 8c 跨度大、组合在价值轴上稀疏。
  这是刻意的取舍（价值曲线平滑优先于件数稳定）。

  [已取消] 原先「二级第 4 回合、三级第 7 回合解锁」的限制：新曲线第 3 回合就超出
  「6 件一级 = 18c」的上限，必须提前放出二级，第 4 回合同理必须放三级。
  代价是第 4~6 回合玩家会撞上自己还合不出来的三级装备。

ENEMY_HP_TABLE
  与 LEVEL_TABLE 联动：装备价值涨了，血量同步下调做补偿，避免「装备变强 + 血量不变」的双重碾压。
  第 1 回合是白给关，且要保持血量单调递增，所以它成了第 2 回合降幅的下限——
  要再弱必须连第 1 回合一起降。

其他：
- 敌人装备按等级从 itemLibrary 随机抽取，不走商店、不花钱。
- 抽池排除 ENEMY_EXCLUDED_BASE_ITEM_IDS（当前蓝水晶）及其全部产物，

十一、已决策的设计取舍
------------------------------------
以下都是考察过、决定保留的，不再是待办：

1. 生命是资源，故意输是合法策略。
   失败不推进回合，失败场同样拿 BASE_INCOME，输一场 11c 只比赢一场 12c 少 1c，
   于是「先故意输几场攒钱 + 攒回合，再一路赢到底」成立。这是刻意的，不是缺口：
   生命（心）本身就是可消耗资源，拿生命换经济是策略的一部分。
   满血通关是「运气 + 策略双在线」的证明，是本作的技术上限；
   做不到满血也可以拿血换钱过关，是留给玩家的退路。不做防连败机制。
   [边界] 该策略的收益被 3 颗心限死；且失败场不推进回合 = 那一场不产生进度，
   心耗尽本局即结束。
2. 敌人抽卡方差：二级 / 三级装备池内等概率（一级装走商店池的库存加权），
   抽到 2 件无尽之刃与抽到 2 件纯防御装，强度差一倍以上。
   评估后决定暂不收敛，等实测有明确体感再给二级 / 三级配权重。
3. 同材料重复配方（见三节）：同一组材料能做出多件装备，由玩家按本局阵容自己选。
   三级阶段尤其密集，是刻意保留的产物多样性。
4. 平衡未校准：三级装备强度、敌人 HP 曲线、经济节奏只在纸面推演过，未实测。
   全局平衡等所有装备添加完毕后再统一校准，届时再讨论是否逐件调。
5. 护盾无上限、无衰减。
6. 附加伤害吃自己（发电机 / 火炬）、伤害倍率给提供者自己加成（无尽之刃）：
   面板上看不见的隐性收益，可接受。
7. 超时类装备（基克 / 猎魔人弩箭）在没打到超时的情况下是白板，暂不加「超时前补偿」。

十二、待决策 / 待实测
------------------------------------
1. 破舰者要求「己方装备栏全是三级」，6 格棋盘的经济压力极大，需实测判断是否形同虚设。
2. 探索者的护臂 / 翠绿屏障是「打魔法 + 抗物理/魔法」的针对装，
   与「减少针对型防御装挫败感」的目标冲突，留不留待定。
3. 三级 54 件全靠合成表与商店随机，没有「本局推荐阵容」之类的引导。
4. 穿透件「一点穿透值多少伤害」未定死，将来二级 / 三级需要一个统一单价，
   否则每件都得单独推一遍。
5. 未做：攻速 / 暴击 / 韧性 / 控制类特效（冻结、麻痹、灼烧、减攻、沉默、破甲、破魔）、
   相邻加成 / 羁绊 / 阵营系统、重铸。

[技术限制] conditionalStats 读不到「装备需要的聚合值」（如界弓要读敌方抗性），
         只能在 damageType 这类构造函数声明过的字段上做文章，写法受限（见四节）。
         这类读取也不能写进棋子自己的 conditionalStats：敌我双方都有同款装备时会走成
         computed 互相依赖的环，Vue computed 重入求值直接爆栈。


十三、改数值去哪改
------------------------------------
| 想改什么 | 去哪改 |
| 初始金币 / 生命 / 白送装备 / 基础 HP | gameConfig.js |
| 棋盘 / 仓库 / 商店格数 | gameConfig.js（SHOP_SLOT_TABLE + getShopSlots） |
| 战斗时长 / 回合数 / 超时惩罚 / 抗性常数 / 有效抗性下限 | gameConfig.js |
| 经济（收入 / 胜负奖励 / 刷新费 / 出售比例） | gameConfig.js |
| 敌人波次表 / 敌人血量表 / 抽池排除项 | gameConfig.js |
| 商店各等级权重 / 一级装池子初始库存 | gameConfig.js |
| 单件装备的数值与效果 | itemLibrary.js 的 stats / cooldown / effect / hooks |
| 合成配方 | recipes.js（价值与买入价自动推导，不要手填） |
| 抽卡逻辑 | itemLibrary.js 的 drawItem |
| 商店池的进出账（预留 / 归还 / 豁免） | itemPool.js |

改 BOARD_SLOTS 时有两处必须同步，否则会错位或截断：
- merge.vue 的 .board 样式写死了 3×2 布局；
- ENEMY_LEVEL_TABLE 每回合三项之和不能超过 BOARD_SLOTS，
  超出部分会被 enemyBuilder 直接丢弃，敌人强度低于表格预期。
